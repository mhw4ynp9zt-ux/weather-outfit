# 天気×服装提案アプリ 設計書(短縮版)

日付: 2026-11-16 / 状態: 承認待ち

## 目的(なぜ)
その日に何を着るかを、天気予報から素早く決めたい。1週間先まで見えて、時間帯ごとの気温差も踏まえ、自分(暑がり寄り)の感覚に合う提案がほしい。

## ゴール
- 7日分の日付タブから日を選ぶと、朝・昼・夜の服装と1日のまとめが出る
- 寒がり/普通/暑がりの設定で提案が変わる(初期値: 暑がり)
- ホーム画面に追加でき、アプリのように起動できる(PWA)
- 前回取得した予報はオフラインでも見られる

## 非ゴール(初版)
手持ち服の登録、アカウント・複数端末同期、プッシュ通知、コーデ画像、サーバー側の処理

## アンチゴール
- 気温の数字を並べただけで、服装の結論が出ない
- 設定や場所を毎回入力し直させる

## 画面
上部: 7日分の日付タブ(曜日・天気アイコン・最低〜最高気温)
下部: 選択日の
- 朝(7〜9時)/昼(12〜15時)/夜(18〜22時)それぞれの気温・体感・降水確率と、アイテム(絵文字付き)+一言の理由
- 1日を通したまとめ1行(例: 脱ぎ着しやすいコート+傘)
- 設定: 場所(初期値 東京、都市名検索、現在地)、寒がり度、時間帯の変更

## 選択したアプローチ
- **A. 単一HTML**: サーバー不要、直しやすい
- B. サーバー付き: 今回は過剰
- **C. A+PWA(採用)**: ホーム画面に追加でき、オフラインにも強い。
  → ユーザーの選択。実装は静的ファイル一式(index.html / manifest.webmanifest / sw.js / アイコン)。

## 決定事項(ユーザーが決めたもの)
7日表示、時間帯分け、暑がり、PWA

## 私の判断(要確認)
- 天気データはOpen-Meteo(無料・キー不要、時間別予報あり)
- 設定・場所・最後の予報はlocalStorage、予報取得はnetwork-first、失敗時は保存分を表示
- 服装は体感温度(気温・風・湿度)を5〜6段階に分け、雨・風・紫外線で小物を足す。暑がりは段階を高温側へ1つずらす
- 時間帯の既定値は朝7〜9/昼12〜15/夜18〜22時

## 制約
ホーム画面追加とオフライン動作にはHTTPS配信が必要(ローカルファイル直開きでは不可)。配信先はCloudflare Pages(ユーザー決定)。

## 実装者に任せること
温度帯の境界値、アイテム文言、配色・アイコン、エラー表示
